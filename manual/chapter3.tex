\section{ความต้องการของระบบ}

\subsection{ระบบปฏิบัติการ}

คู่มือนี้อธิบายการติดตั้งบนระบบปฏิบัติการ Windows 11

\subsection{ซอฟต์แวร์และบริการที่ต้องเตรียม}

\begin{parenlist}
\item Node.js เวอร์ชัน 20 ขึ้นไป (ระบบ CI ใช้เวอร์ชัน 20) สำหรับส่วนติดต่อผู้ใช้งานและบริการข้อมูลหลัก
\item Python เวอร์ชัน 3.11 สำหรับ AI Service
\item Git สำหรับดาวน์โหลดซอร์สโค้ดจาก GitHub
\item Visual Studio Code สำหรับเปิดและแก้ไขโครงงาน
\item บัญชี Supabase สำหรับฐานข้อมูล PostgreSQL
\item บัญชี Cloudinary สำหรับจัดเก็บรูปภาพ
\item บัญชี Gmail ที่เปิดการยืนยันตัวตน 2 ขั้นตอนและสร้าง App Password สำหรับส่งอีเมล
\item โปรเจกต์ Google Cloud ที่เปิดใช้ Places API (New) และ Maps JavaScript API
\item คีย์ KKU AI Gateway สำหรับเรียกใช้โมเดลภาษาขนาดใหญ่
\item คีย์ Serper API (ไม่บังคับ) สำหรับสคริปต์สร้างคำอธิบายสถานที่
\end{parenlist}

\subsection{การสร้างฐานข้อมูลบน Supabase}

\begin{numlist}
\item เข้าเว็บไซต์ https://supabase.com/ ลงชื่อเข้าใช้ แล้วสร้างโปรเจกต์ใหม่ พร้อมบันทึกรหัสผ่านฐานข้อมูลที่กำหนดไว้
\item เปิดหน้า Project Settings > Database > Connection string แล้วคัดลอก Session pooler (พอร์ต 5432) เพื่อนำไปกำหนดเป็นค่า \texttt{DATABASE\_URL} ไม่ควรใช้ Transaction mode (พอร์ต 6543) เนื่องจาก backend เป็นเซิร์ฟเวอร์ที่ทำงานต่อเนื่อง
\item เปิดหน้า Project Settings > API แล้วคัดลอก Project URL และ service\_role key เพื่อนำไปกำหนดเป็นค่า \texttt{SUPABASE\_URL} และ \texttt{SUPABASE\_SERVICE\_ROLE\_KEY} ซึ่งทั้ง AI Service และสคริปต์นำเข้าข้อมูลของ backend ใช้งาน
\item สร้างโครงสร้างตารางด้วยการนำไฟล์ migration ไปใช้กับฐานข้อมูลใหม่ ตามขั้นตอนในหัวข้อการนำเข้าข้อมูลตั้งต้น
\end{numlist}

\subsection{การตั้งค่าไฟล์ .env}

ไฟล์ \texttt{.env} คือไฟล์ที่ใช้เก็บตัวแปรสภาพแวดล้อม (environment variables) ซึ่งเป็นค่าตั้งต้นที่โปรแกรมอ่านตอนเริ่มทำงาน เช่น ที่อยู่ของฐานข้อมูล รหัสผ่าน คีย์ของบริการภายนอก และที่อยู่ที่แต่ละส่วนของระบบใช้ติดต่อกัน การแยกค่าเหล่านี้ออกจากซอร์สโค้ดทำให้เปลี่ยนค่าตามเครื่องหรือสภาพแวดล้อมที่ใช้งานได้โดยไม่ต้องแก้โปรแกรม และไม่ต้องนำข้อมูลลับไปไว้ในซอร์สโค้ด หากไม่กำหนดค่าที่จำเป็น ส่วนนั้นของระบบจะไม่สามารถเริ่มทำงานหรือเชื่อมต่อบริการที่เกี่ยวข้องได้ ทั้งนี้ ต้องเริ่มการทำงานของระบบใหม่ทุกครั้งหลังแก้ไขไฟล์ \texttt{.env}

แต่ละส่วนมีไฟล์ \texttt{.env.example} เป็นต้นแบบ ให้คัดลอกเป็นไฟล์ \texttt{.env} ในโฟลเดอร์เดียวกัน แล้วกรอกค่าตามตารางที่ \ref{tab:env-vars} ไฟล์ \texttt{.env} มีข้อมูลลับ จึงห้ามบันทึกเข้าระบบ Git

\begin{codeblock}
\begin{lstlisting}[numbers=none]
cd backend
copy .env.example .env
cd ../frontend
copy .env.example .env
cd ../chatbot-service
copy .env.example .env
\end{lstlisting}
\end{codeblock}

\subsection{การนำเข้าข้อมูลตั้งต้น}

ขั้นตอนนี้ดำเนินการเพียงครั้งเดียวตอนติดตั้งฐานข้อมูลใหม่ โดยใช้ Terminal ที่โฟลเดอร์ \texttt{backend}

\begin{codeblock}
\begin{lstlisting}[numbers=none]
cd backend
npx supabase db push --yes
npm run fetch:places
npm run import:places
npm run seed:events-knowledge
\end{lstlisting}
\end{codeblock}

ความหมายของแต่ละคำสั่งมีดังนี้

\begin{numlist}
\item \texttt{npx supabase db push --yes} สร้างตารางและฟังก์ชันตามไฟล์ migration ใช้กับฐานข้อมูลใหม่เท่านั้น เนื่องจากฐานข้อมูลที่ใช้งานจริงอยู่แล้วไม่มีประวัติ migration ทำให้คำสั่งนี้ประมวลผล migration เดิมซ้ำทั้งหมด
\item \texttt{npm run fetch:places} เรียกข้อมูลสถานที่จาก Google Places API และบันทึกลงไฟล์ \texttt{backend/data/places.json} ซึ่งมีค่าใช้จ่ายตามจำนวนสถานที่
\item \texttt{npm run import:places} นำเข้าข้อมูลจากไฟล์ดังกล่าวเข้าฐานข้อมูล
\item \texttt{npm run seed:events-knowledge} เพิ่มข้อมูลกิจกรรมและฐานความรู้ตั้งต้น
\end{numlist}

หลังนำเข้าข้อมูลใหม่ทุกครั้ง ต้องสร้าง Embedding ใหม่ เพื่อให้แชตบอตและระบบวางแผนทริปสามารถค้นหาข้อมูลที่เพิ่มเข้ามาได้

\begin{codeblock}
\begin{lstlisting}[numbers=none]
cd chatbot-service
venv\Scripts\activate
python scripts/embed_content.py
\end{lstlisting}
\end{codeblock}

\subsection{การสร้างบัญชีผู้ดูแลระบบ}
\label{sec:create-admin}

บัญชีผู้ดูแลระบบสร้างด้วยสคริปต์ที่โฟลเดอร์ \texttt{backend} โดยระบุอีเมลและรหัสผ่านที่ต้องการ

\begin{codeblock}
\begin{lstlisting}[numbers=none]
cd backend
node scripts/create-admin.js <email> <password>
\end{lstlisting}
\end{codeblock}

\subsection{การสร้างและเริ่มระบบด้วย Docker Compose}

เมื่อกำหนดค่าครบแล้ว ให้สร้างภาพและเริ่มบริการทั้งหมดที่โฟลเดอร์ \texttt{deploy}

\begin{codeblock}
\begin{lstlisting}[numbers=none]
cd deploy
docker compose up -d --build
\end{lstlisting}
\end{codeblock}

การสร้างครั้งแรกใช้เวลาค่อนข้างนาน เนื่องจากต้องดาวน์โหลดไลบรารีและโมเดลสำหรับสร้าง Embedding หลังเริ่มบริการแล้ว สามารถตรวจสอบสถานะและบันทึกการทำงานได้ด้วยคำสั่งต่อไปนี้

\begin{codeblock}
\begin{lstlisting}[numbers=none]
docker compose ps
docker compose logs --tail 50 chatbot
docker compose logs --tail 50 backend
\end{lstlisting}
\end{codeblock}

จากนั้นเปิดเบราว์เซอร์ไปที่ \texttt{https://<CHAT\_DOMAIN>/health} หากบริการ AI Service พร้อมใช้งานจะตอบกลับสถานะปกติ ทั้งนี้ หลังเริ่มบริการใหม่ AI Service ต้องใช้เวลาโหลดโมเดลก่อน จึงอาจยังไม่ตอบกลับทันที

ระบบจำกัดขนาดบันทึกการทำงานของแต่ละบริการไว้ที่ 3 ไฟล์ ไฟล์ละไม่เกิน 10 MB เพื่อป้องกันพื้นที่จัดเก็บเต็ม และตั้งให้บริการทุกตัวเริ่มทำงานใหม่เองเมื่อหยุดโดยไม่ได้ตั้งใจ (\texttt{restart: unless-stopped})

\subsection{การปรับปรุงระบบด้วยสคริปต์ deploy.sh}

เมื่อมีการแก้ไขโค้ดและต้องการปรับปรุงระบบบนเซิร์ฟเวอร์ ให้ใช้สคริปต์ \texttt{deploy/deploy.sh} ซึ่งดำเนินการตามลำดับดังนี้

\begin{numlist}
\item ดึงโค้ดล่าสุดของสาขา \texttt{main} จาก GitHub โดยอนุญาตเฉพาะการรวมแบบ fast-forward
\item อ่านเลขเวอร์ชันจากไฟล์ \texttt{VERSION} และรหัส commit เพื่อแสดงในหน้าผู้ดูแลระบบ
\item สร้าง image ของบริการ \texttt{chatbot}, \texttt{backend} และ \texttt{caddy} ทีละบริการ เพื่อป้องกันไม่ให้หน่วยความจำของเซิร์ฟเวอร์ไม่เพียงพอ
\item เริ่มบริการด้วย \texttt{docker compose up -d} แล้วสั่งให้ Caddy อ่านไฟล์ตั้งค่าใหม่
\item ตรวจสอบที่ \texttt{/health} ซ้ำไม่เกิน 3 นาที หากสำเร็จจะแสดงข้อความ ``deploy ok'' แต่หากไม่สำเร็จจะแสดงบันทึกการทำงานของ \texttt{chatbot} ล่าสุดและจบด้วยสถานะผิดพลาด
\end{numlist}

\begin{codeblock}
\begin{lstlisting}[numbers=none]
bash deploy/deploy.sh
\end{lstlisting}
\end{codeblock}

ข้อควรระวัง สคริปต์นี้ไม่ได้นำไฟล์ migration ของฐานข้อมูลไปใช้ หากมีการเปลี่ยนโครงสร้างตาราง ต้องนำไฟล์ migration ใหม่ไปใช้กับฐานข้อมูลก่อนด้วยตนเอง ตามที่อธิบายในหัวข้อการนำเข้าข้อมูลตั้งต้น
